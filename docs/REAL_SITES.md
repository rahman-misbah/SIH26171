# Edward — Real-site pass

Generated by `npm run realsites -- --label "<machine>"` (M12, SPEC §18.1 on real pages). Each
site in `tests/realsites/sites.ts` is loaded logged out on a fresh profile, and the e2e build's
hook runs one observation with the **mock backend**: nothing goes to a reasoning backend. Only
counts and timings are recorded. Page text never leaves the test process.

Reading the tables:
- **outcome**: `ok`; `blocked` (the §14 final guard withheld the observation); `timeout` (no
  observation within 120 s); `error`; `nav_failed` (the page didn't load).
- **observe ms**: wall time of the whole observation in the content script (Phase A, Phase B,
  images the assembler waits for, assembly).
- **tokens**: distinct `[PII_<TYPE>_n]` tokens in the outgoing observation.
- **leak candidates**: regex-tier hits left in the outgoing text (`src/sanitize/residualScan.ts`).
  The pipeline tokenizes every regex hit except emails the §7.5 heuristic keeps public, so any
  count here is investigated. Emails with a public signal (role address or same-site domain) are
  counted separately as `EMAIL_LIKELY_PUBLIC` in the second table.
- Per-op columns are p50 / p95 ms from the metrics log over that site's visit.


What the pass found (M12, first run on the dev laptop, before any fix):
- **Latency.** Observations took 28–95 s (The Hindu 94 s, YouTube docs 39 s, Flipkart 36 s,
  isro.gov.in 28 s), and Wikipedia ran past the 120 s timeout. NER on every text unit (thousands per
  page, about 50 sequences/s) was nearly all of it. Visiting the sites in one browser also queued
  each page's work behind the previous one, so every later site timed out too. Fixed by the §14.2
  budget applied before sanitization and length-bucketed NER batches (SPEC §0.1 F1–F2). Phase A on
  Wikipedia also went from 4.7 s to 1.1 s (F7).
- **A crash on india.gov.in.** An element id containing a newline broke a `label[for="…"]` selector
  and failed the whole observation (fail closed, but useless). Fixed (F7).
- **No leaks.** 0 leak candidates in every observation that completed, before the fixes (9 of 11
  sites, run one at a time) and after (all 11).
- **Stack Overflow** served a bot-check page to the automated browser (3 nodes), so it measures
  that page, not the question.
- `cors_blocked` / `unreadable` reasons are cross-origin images the fallback fetch couldn't read.
  They're withheld with a marker, as designed. `egress_blocked` is MediaPipe's metrics upload,
  refused.
